# Дизайн: объёмы партии и отдельная проверка цены

## Назначение

Дать пользователю возможность менять объём материала и работы прямо в таблице, считать материалы по размеру партии, а стоимость изготовления — по единичным нормам, умноженным на тираж. В заголовках цехов показывать стоимость на одно изделие и на всю партию. В блоке проверки цены показать раздельные материальные затраты, изготовление, себестоимость, цену и прибыль до/после налога на прибыль.

## Границы

- Сохраняется существующая модель `qty` + `scope`; миграция старых расчётов не нужна.
- Объём строки работы остаётся единичной нормой для `scope=unit`; денежная сумма работы рассчитывается для партии.
- Материальные строки продолжают учитывать запас, закупочную кратность и отнесение закупки.
- «Изготовление» означает строки работ с категорией `production`; проектирование, монтаж и доставка не включаются в этот показатель.
- Налог на прибыль — редактируемая ставка расчёта, по умолчанию 25%. Налог считается от прибыли до налога, если расчёт полный; при неполном расчёте значение остаётся неизвестным.
- Входной НДС материалов считается уже включённым в исходные цены и отдельно из себестоимости не вычитается.

## Подходы

1. Минимальная правка текущих `app.js`/`engine.js`/`review-ui.js` и CSS — выбранный вариант. Сохраняет совместимость старых JSON.
2. Новая модель с отдельными полями единичного и партийного объёма — точнее, но требует миграции и затрагивает архивы.
3. Только визуальное форматирование — не покрывает налог на прибыль и расчёт изготовления.

## Изменения

1. В таблицах материалов и работ добавить компактное поле объёма с сохранением по `change`/`blur`; редактирование использует существующую валидацию строки и не открывает карточку.
2. В заголовке каждого цеха показывать `изготовление/процессы: ₽/шт. · ₽/партия`, рассчитывая суммы из строк этого цеха.
3. В параметры цены добавить `profitTax` (25 по умолчанию), сохранить в расчёте и валидировать как неотрицательный процент.
4. В результате добавить отдельный блок «Проверка цены» с показателями на единицу и на партию: материалы, изготовление, себестоимость с НДС, стоимость с прибылью, прибыль до налога и прибыль после налога на прибыль. Для неполных данных использовать `—`.
5. Разделить денежные колонки таблицы работ на ширины/переносы, чтобы сумма и подпись подготовки не выходили из своих колонок.

## Проверка

- Добавить регрессионную проверку: при `qty=10` единичный объём работы не меняется, сумма работы равна единичной стоимости × 10; материал меняет потребность и закупку.
- Проверить 25% налога на прибыль и сохранение старого расчёта без `profitTax`.
- Запустить профильные проверки UI и расчётов, затем `node run-checks.cjs`.
