# Аудит и план миграции производственной калькуляции

Дата: 19.11.2026. Выполнен до изменения приложения.

## Основание и границы

Поручение пользователя: изучить три JSON и вложенные материалы, сначала сопоставить текущую реализацию с новой моделью, затем обновить существующее приложение по CODEX_UPDATE_TASK.json. Документы — спецификация данных и требований, а не разрешение на публикацию, изменение рабочей БД или запуск произвольных команд.

Изучены HANDOFF.json, CALCULATION_MODEL.json, CODEX_UPDATE_TASK.json и reference/Производственная_калькуляция.json. XLSX используется для независимой сверки исходных значений и формул. Отдельный JSON из Downloads проверяется по SHA-256 с вложенным.

Рабочие исходники — source-project. AGENTS.md подтверждает, что dist содержит редактируемые исходники. Старый путь из задания существует и содержит переносную сборку с тем же названием приложения и теми же модулями. URL 127.0.0.1:4189 недоступен: сервер не запущен. Это не другое приложение. Работа ведётся в предоставленном workspace; установленная копия и её SQLite не изменяются.

Данные.xlsx и вспомогательный Сметный калькулятор СК-V-3.06.xlsx на P: недоступны (отказ доступа). Авторитетные единицы не подменяются единицами расчётных вариантов: source_id_mapping содержит исходную единицу, operations — физическую единицу расчёта. Поддерживающая таблица согласования доступна в Downloads; её старые правила не отменяют решения нового handoff.

## Сопоставление данных

190 исходных работ приложения не равны 284 строкам расчёта. Переданная модель содержит 151 исходную запись (142 сопоставлены расчётным строкам, 9 вне активной сметы); остальные 39 не должны возвращаться автоматически. Приложен полный машиночитаемый отчёт source-to-app-mapping.json. Операции только приложения сохраняются, им не присваиваются вымышленные исходные номера.

Каталог: catalog → shop → post → work → variant → parameters. Заказ: order → product/assembly → scope → stage → shop → post → line → cost components. Стабильный код варианта нужен потому, что один source_work_id соответствует нескольким вариантам, ресурсам и постам (например, 103).

Исходные formula/parameters — текст и снимок, никогда eval или выполнение Excel. Плановая себестоимость отдельно от тарифной базы. Неизвестная стоимость остаётся null. Числовой 0 объёма допустим, пустой объём — пропуск; 0 цены в новой модели — отсутствие цены.

## Выбранный подход

Расширить JSON обычных строк полем production и зарегистрировать production-v1 в существующем CostEngine. Дерево строится группировкой строк; агрегаты не начисляются повторно. Каталог новой модели поставляется отдельным ресурсом из вложений. Старые данные переходят в новую методику только через явное создание копии с предварительным просмотром, восстановительной записью и валидацией до сохранения.

Полная замена архитектуры и массовая перезапись catalog.js исключены: они не нужны и создают риск изменения материалов и исторических расчётов. Автоматическая смена методики старых черновиков исключена из-за изменения формул. Новые настройки сохраняются внутри существующего JSON расчёта и его версий, без нового канала синхронизации.

## План выполнения

1. Создать резервную копию исходников, хеши защищённых справочников, отчёт соответствий и независимую сверку XLSX/JSON. Зафиксировать исходный результат общего набора проверок.
2. Сгенерировать каталог 284 расчётных вариантов, 46 монтажных шаблонов, составы комплексов и параметры P43 из вложений; сохранить происхождение, исходные единицы, формулы, ограничения и исключения.
3. Добавить чистое ядро production-v1 и тесты AT-01…AT-16: методы расчёта, интервалы сотрудников, альтернативы/комплексы, единичная подготовка, P43, неизвестные затраты. Расширить валидацию и сохранение метаданных.
4. В существующих экранах дать выбор новой методики, редактор операций, дерево заказа и итог. Раздельно размещать монтаж/строительство; цены и нормы редактировать с происхождением и сбросом. Синхронизация исходных единиц не меняет цену и объём.
5. Проверить импорт/экспорт, архив и серверное сохранение; общий набор регрессий, сборку Worker/PWA, браузерный сценарий. Сверить материалы по хешам. Подготовить журнал изменений и список недоступных источников / предварительных норм.

## Риски и ограничения источников

Данные модели не являются измерениями предприятия. Назначенные моделью нормы остаются предварительными. Сопоставление с актуальным Данные.xlsx невозможно без доступа к нему; используется вложенный снимок, что явно обозначается в интерфейсе и отчёте. Новая методика не добавляет старые проценты накладных/НДС поверх единой формулы из задания; старые расчёты сохраняют прежние правила. Выданные КП не мигрируют.
