# Производственная модель / 19.11.2026

## Совместимость

Схема калькуляции остаётся 1/2/3. Новая методика — `engineVersion: "production-v1"`; старые `cost-v1` и `cost-review-v1` сохраняются. SQL и формат протокола ревизий не меняются. Обновлены только допустимые JSON-поля и регистрация дополнительного справочника.

Обычные строки материалов сохраняются. Производственная строка имеет прежние `id`, `kind`, `qty`, `price`, `scope`, `pack`, `reserve` и дополнительный объект:

```json
{
  "production": {
    "definition": {
      "id": "production-Р112",
      "code": "Р112",
      "source_work_id": 112,
      "source_record": "Перечень_работ:112",
      "name": "Управляющая программа для лазерной резки",
      "scope": "product_manufacturing",
      "stage": "preparation",
      "shop_id": "ЧПУ цех",
      "post_id": "P02",
      "unit": "м контура",
      "calculation_method": "unique_program_prep",
      "quantity_basis": "Уникальные контуры без умножения на тираж",
      "financial_basis": "Данные.xlsx, Перечень_работ!F112; вложенный снимок",
      "origin": "dialogue",
      "status": "needs_review",
      "pricing": {},
      "cost_model": {}
    },
    "inputs": {"quantity": 240, "unique_program_id": "Программа 1"},
    "productId": "Изделие А",
    "segment": "Левый каркас",
    "workPackage": "Заказ 1",
    "selected": true
  }
}
```

Пример показывает размещение и идентичность; при создании строки pricing и cost_model берутся из полного каталога или заполняются в редакторе. `definition` — снимок, обновление справочника не заменяет его автоматически. `source_work_id` относится к исходной строке, `code` различает несколько вариантов той же работы. `scope` внутри definition — область работ; прежний `line.scope` — кратность на изделие/партию. Объёмы нового редактора вводятся на весь заказ.

`pricing` содержит base_unit_price, current_unit_price, manual_override, source_formula, source_parameters, formula_note и note. Для норм времени хранится исходная hourly_rate / base_hourly_rate. Редактируется текущая физическая ставка; часовая ставка источника показана справочно. Сброс возвращает исходные ставки и пояснение. Источник Excel не выполняется. Полная точность сохраняется, денежное представление — два знака.

`cost_model.unit_cost` — базовые плановые затраты на физическую единицу, null означает неизвестное. Для циклов бригады труд рассчитывается по текущему времени/составу и labor_cost_per_person_hour, расходники отдельно. Ручное изменение удельных затрат записывается также в unit_cost_override. Дополнительные поля ресурсов сохраняются вместе с исходными параметрами. Входы содержат фактический объём, человеко-/машино-часы, обозначение партии/программы, режим P08, параметры пакетного распила, коэффициент труда, интервалы работников либо карту P43.

Каталог базовых вариантов — production-catalog.js, генерируется из вложенного снимка. Пользовательские настройки — объект `izdelie-production-catalog-v1`, по одной записи на id через существующий RecordProtocol. Импорт валидируется до записи и сохраняет локальную восстановительную копию. При облачном конфликте обе отличающиеся настройки остаются доступными, местная копия получает новый id и статус проверки.

## Суммирование

Дерево — представление тех же строк: изделие → область → этап → цех → пост → строки → компоненты. Родитель с `parentLineId` у дочерних строк показывает их сумму справочно. В общий итог входят только начисляемые строки. Альтернативы проверяются в пределах изделия, пакета и физического участка; монтажные агрегаты 34/35/49 не допускаются вместе с детализацией того же участка.

`preMarkupBase` — тарифная база выбранных строк; `total = round(preMarkupBase × 1.40, 2)`. `plannedCost` — отдельная сумма затрат, `profit = total − plannedCost`; margin представляется в процентах, как в прежнем интерфейсе. При неизвестных затратах plannedCost/profit/margin равны null и profitIncomplete=true. Старые накладные/транспорт/НДС не накладываются на новую формулу: в production-v1 фиксируются 0/0/0 и наценка 40. Прочие обоснованные затраты вводятся строками. Клиентские документы используют прежний whitelist.

У операторов 103 вход — машино-часы своего поста или явная связь с выбранными машинными строками того же участка. Фактические интервалы задаются минутами от единого начала заказа; одинаковое имя — один сотрудник. Суммируется объединение интервалов, разные сотрудники складываются. P43 использует полный труд станочника; карта и её самостоятельные ресурсные строки вместе блокируются.

У P43 каждая строка задаёт толщину, физическую длину пропила, ходы, листы и необязательный измеренный чистый цикл. Пустые ходы/листы рассчитываются по явно обозначенным предварительным нормам; явный 0 листов сохраняется. Наладка и подача отделены от чистого цикла; помощник и новая карта вводятся человеко-часами. Измеренный цикл заменяет расчётное время. Ширина пропила 3 мм не добавляется к метрам реза.

Ресурсные составы прежних комплексов сохраняются в reference_components; коммерческая тарифная база не заменяется их суммой. Для нового комплекса с дочерними строками применяется сумма детей без повторного начисления родителя.

## Миграция и источники

В интерфейсе: «Перейти на новую методику с сохранением копии» → предпросмотр → отдельная рабочая копия. Восстановление — прежний механизм «Восстановить предыдущий расчёт» в базе изделий. Сохранённые версии изделий и выпущенные КП не изменяются.

В файлах: `node tools/migrate-production-calculation.cjs старый.json новая-копия.json`. Скрипт отказывается перезаписывать существующий файл; исходник остаётся неизменным. Неоднозначные варианты и единицы требуют проверки; старые цены и количества не конвертируются. Несопоставленные работы требуют явного выбора нового варианта и не входят в согласованный итог.

Для доступного проверенного Данные.xlsx используется прежний `tools/read-production-workbooks.ps1`. Его JSON передаётся в `node tools/sync-production-source.cjs источник.json настройки.json экспорт-текущих-настроек.json`; затем настройки импортируются через каталог операций. Синхронизация меняет единицу при изменении исходной единицы, сохраняет цену и объём, показывает предупреждение до сохранения настройки. Новые работы добавляются, исключённые исходные записи не восстанавливаются. Старые пользовательские определения сохраняются; генератор источника не заменяет существующий пользовательский справочник.

Актуальный Данные.xlsx недоступен, поэтому первоначальное обновление использует приложенный снимок. Физическая единица варианта и исходная единица source_unit хранятся раздельно. Текущая первичная таблица не считается проверенной.
